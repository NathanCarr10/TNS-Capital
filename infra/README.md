# TNS Capital on AWS (OpenTofu)

Deploys the platform to the LEAP training account (eu-west-1), following the Sprint 11
layout: the Angular app in S3 behind CloudFront, the services as ECS Fargate tasks,
Postgres on RDS, and secrets in Secrets Manager.

```
Browser ──HTTPS──> CloudFront ──> S3 (Angular build)            default path
                        │
                        └──HTTP──> ALB ──> /api/v1/strategies*  strategy-service
                                       ──> /api/*               app
                                       ──> /auth/*              auth-service
                                       ──> /analytics*          dashboard
ECS tasks find each other as <service>.<prefix>.internal (Cloud Map):
  app ──> kafka, broker-simulator     strategy-service ──> app, auth-service
  every service ──> RDS (private, 5432 from the tasks only)
```

CloudFront forwards the API paths to the ALB, as `frontend/nginx.conf` does locally, so
the browser only ever talks to one origin and the app needs no URL or CORS changes. The
ALB accepts CloudFront's addresses only.

## What is different from docker-compose

| Compose | AWS | Why |
|---|---|---|
| `postgres` container, init scripts on first start | RDS Postgres 16; `scripts/init-db.sh` runs the `db/` image once as an ECS task | RDS does not run `docker-entrypoint-initdb.d` |
| `.env` | One Secrets Manager secret, generated by `secrets.tf`; the master DB password is RDS-managed | No secret in an image or in git |
| Kafka container | One KRaft node on Fargate, image mirrored into ECR | The private subnets have no route to Docker Hub; MSK costs far more |
| nginx container | CloudFront (routing, security headers, SPA fallback function) | Static files from S3 |
| VictoriaMetrics, vmalert, VictoriaLogs | The same images on Fargate, with `observability/`'s configs baked in by `scripts/push-images.sh` | Fargate has no bind mounts. Their data is on the task's own disk, so a restart or a pause starts the history again |
| Fluent Bit reading Docker's log files | `observability/log-forwarder`: copies `/ecs/<prefix>/*` from CloudWatch Logs into VictoriaLogs every 5 s | Fargate has no log files to tail. CloudWatch Logs, alarms and a CloudWatch dashboard are there as well |
| kafka-ui | Not deployed | Admin tool, no login |

Two settings are AWS-only: `PGSSLMODE=no-verify` for the auth service (RDS refuses
unencrypted connections and its `pg` Pool sets no `ssl` option), and
`AUTH_TRUST_PROXY=2` (CloudFront and the ALB both add to `X-Forwarded-For`).

`app` and `etl` call the Alpaca API. With Alpaca keys set they run in public subnets
with a public IP (inbound is still only the ALB and the other tasks), which avoids a
NAT gateway; without keys they stay private.

## Shared account rules

- The default VPC, its subnets and the VPC endpoints belong to the instructor. This stack
  only reads them (`training.tfvars`); `tofu destroy` never touches them.
- Every name starts with `prefix` (`tns-capital`), the team's shared stack. A teammate wanting a separate copy uses their own tfvars file and prefix.
- Everyone in the account is an administrator, so the state file is encrypted with
  OpenTofu's state encryption (`versions.tf`). This makes the code OpenTofu-only.

## First deployment

```bash
source ~/leap-env.sh
source ~/.tns-tofu.env     # TF_VAR_state_passphrase (+ TF_VAR_alpaca_*); never commit it
cd infra

# Once per account: the state bucket (local state, holds no secrets)
tofu -chdir=bootstrap init && tofu -chdir=bootstrap apply -var prefix=tns-capital
cp backend.hcl.example backend.hcl    # put in the bucket name it printed
tofu init -backend-config=backend.hcl

# 1. Repositories, then images (tagged with the commit SHA)
TAG=$(git rev-parse --short HEAD)
tofu apply -var-file=training.tfvars -var image_tag=$TAG -target=aws_ecr_repository.this
scripts/push-images.sh $TAG

# 2. Everything else, with no tasks running yet (RDS takes 5-10 minutes)
tofu apply -var-file=training.tfvars -var image_tag=$TAG -var desired_count=0

# 3. Schema, roles and seed data into RDS (once per new database)
scripts/init-db.sh            # --reset drops and recreates a half-initialised database

# 4. Start the services
tofu apply -var-file=training.tfvars -var image_tag=$TAG

# 5. The Angular app
scripts/publish-frontend.sh

tofu output url
```

Services that start before Kafka is up restart until it is; give them a few minutes
after step 4. Logins are in `tofu output logins`, and the passwords
in the secret (`tofu output secret_arn`).

## Deploying a new version

```bash
TAG=$(git rev-parse --short HEAD)
scripts/push-images.sh $TAG
tofu apply -var-file=training.tfvars -var image_tag=$TAG
scripts/publish-frontend.sh       # if the frontend changed
```

ECS rolls each service with no downtime: the old task keeps serving until the new one
passes the ALB health check. If a new version never gets healthy, the old one stays up;
fix it and apply again, or apply the previous tag. Kafka and the ETL scheduler stop the old task first, since
two of either must not run at once.

Or all of it in one go: `scripts/deploy.sh $TAG`. It stops
before applying if the plan changes anything besides task definitions and services.

## Pausing overnight (keeps the data)

```bash
# Stop the tasks and pause the database
tofu apply -var-file=training.tfvars -var image_tag=<live tag> -var desired_count=0
aws rds stop-db-instance --db-instance-identifier tns-capital-db
# Start again (RDS takes about 5 minutes)
aws rds start-db-instance --db-instance-identifier tns-capital-db
aws rds wait db-instance-available --db-instance-identifier tns-capital-db
tofu apply -var-file=training.tfvars -var image_tag=<live tag>
```

About $0.05 an hour while paused (the ALB, plus storage), against about $0.30 running. AWS
starts a stopped database again by itself after 7 days.

## Teardown (deletes the database)

```bash
tofu destroy -var-file=training.tfvars -var image_tag=unused
```

Removes everything, **including the RDS database and all its data** (there are no
backups). Only for the end of the project. The state bucket in `bootstrap/` stays.

## Troubleshooting

| Symptom | Look at |
|---|---|
| A service keeps restarting | `aws logs tail /ecs/tns-capital/<service> --since 15m` |
| `CannotPullContainerError` | The image tag was not pushed: `scripts/push-images.sh <tag>` |
| `ResourceInitializationError ... secrets` | The execution role's `read-secrets` policy, or the shared Secrets Manager endpoint |
| Auth service: `no pg_hba.conf entry ... no encryption` | `PGSSLMODE` missing from its task definition |
| `password authentication failed for user "tns_api"` | `scripts/init-db.sh` has not run on this database |
| 502/503 from `/api` | `aws elbv2 describe-target-health` on the target group; Spring takes 1-2 minutes to start |
| 403 from the ALB's own address | Expected: it only accepts CloudFront |
